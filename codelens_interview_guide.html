The 60-Second Elevator Pitch

Say this word-for-word
"I built CodeLens, an open-source Hybrid Graph-RAG platform for codebase intelligence. Standard vector RAG fails on code because embeddings only capture lexical similarity—they have no concept of execution flow or call hierarchies. For example, asking 'What happens when a user logs in?' only retrieves files containing the word 'login', completely missing the chain: login -> authMiddleware -> validateToken -> createSession.

To solve this, CodeLens combines two retrieval streams:
1. Semantic retrieval using AST-derived code chunks indexed in FAISS with local sentence-transformers.
2. Structural graph retrieval using Tree-sitter ASTs mapped into an in-memory NetworkX directed graph capturing CALLS, IMPORTS, CONTAINS, and EXTENDS edges.

At query time, we extract identifiers, run BFS traversal with exponential decay, and merge candidates via a deterministic weighted formula ($0.6 \times \text{Semantic} + 0.4 \times \text{Graph}$). This grounds LLM responses with exact clickable source lines and powers an automated Impact Analysis Engine that calculates what breaks before you touch a function."

The Core Thesis (The "Golden Quote")

The 10-Stage Pipeline Breakdown

1. Ingestion (github_loader.py)

Pre-checks repo size via GitHub API (<100MB limit). Clones --depth 1 into an isolated temp dir. Security: Untrusted code is never executed, built, or installed.

2. File Filtering (file_filter.py)

Filters TS, JS, and Python. Ignores node_modules, dist, .next, __pycache__, minified files (.min.js), and files >1MB.

3. AST Parsing (ast_parser.py)

Tree-sitter extracts symbols, imports, and call sites. Fault-tolerant: falls back to RegexFallbackParser if grammars are missing.

4. Graph Construction (graph_builder.py)

Builds NetworkX MultiDiGraph. Resolves cross-file imports and maps call expressions to callee functions and classes.

5. Structural Chunking (chunker.py)

1 chunk = 1 function/method/class. Prepends metadata file_path | symbol (kind) to code. Caps chunks at 150 lines.

6. Vector Index (vector_store.py)

Uses local all-MiniLM-L6-v2 embeddings. FAISS IndexFlatIP performs exact cosine search in <2ms on CPU.

7. Graph BFS Traversal (graph_query.py)

Matches query symbols, traverses up to depth 2 along CALLS/IMPORTS/EXTENDS edges with exponential decay $0.5^{(d+1)}$.

8. Hybrid Reranking (reranker.py)

Fuses scores: $0.6 \times \text{Semantic} + 0.4 \times \text{Graph}$. Boosts files by $0.35$. Tracks provenance (semantic+graph).

9. Context Building (context_builder.py)

Packs code blocks, line numbers, up to 6 verified relationships per chunk, and graph paths into a strict 24,000 char budget.

10. LLM Generation (llm.py)

Generates answers with exact citations. Zero-Key Fallback: degrades cleanly to retrieval-only mode if no API key is provided.

Architectural Trade-Offs (Why Senior Engineers Choose These)

Q: Why NetworkX instead of Neo4j / Memgraph?

"For codebase graphs (typically 500 to 20,000 nodes), an in-memory NetworkX graph takes less than 20MB of RAM. Neo4j would introduce heavy JVM containers, connection pooling, serialization latency, and operational overhead. NetworkX gives instant in-process BFS, zero external dependencies, and simple disk caching via pickle."

Q: Why FAISS FlatIP instead of Pinecone / Weaviate / HNSW?

"On 2,000 code chunks, an exact inner-product scan on normalized vectors takes under 2 milliseconds on CPU. Approximate indices like HNSW or vector cloud services introduce hyperparameter tuning, network roundtrips, and recurring costs for zero recall improvement at this corpus size."

Q: Why Weighted Fusion (0.6/0.4) instead of a Cross-Encoder Reranker?

"Cross-encoders add 300ms–500ms of GPU latency per query and act as a black box. Our weighted fusion is deterministic, executes in <1ms, allows explainable provenance (showing the user whether code was found via text or graph connections), and is easily tunable."

Q: Why Tree-sitter over regex or compiler frontends (tsc / mypy)?

"Tree-sitter provides a single unified C/Python API across JS, TS, and Python without needing full compiler setups (no node_modules or package managers needed). It handles syntax errors gracefully on active git branches."

15 Hard Interview Questions

We use static lexical binding tables. When file A imports validateToken from ./auth, our parser records the binding. When a call expression validateToken() is encountered, we link it to the exported symbol node in auth.ts. For member calls like user.getName(), if user is instantiated from an imported class, we resolve it against that class's methods.

Repository code is treated strictly as untrusted text data. We never run npm install, pip install, or build tools. When calling git clone, we run in a sanitized subprocess with GIT_TERMINAL_PROMPT=0, a stripped PATH, and a temporary dummy HOME directory so local git hooks and configs cannot fire.

It runs deterministic graph operations: 1. Identifies target symbol node. 2. Collects direct callers (incoming CALLS edges). 3. Runs BFS up to depth 3 to find transitive callers. 4. Collects files importing its module. 5. Filters all affected nodes against a test file regex to identify broken unit tests. 6. Computes impact level (LOW, MEDIUM, HIGH based on caller counts).

The system features Zero-Key Graceful Degradation. Vector embeddings run locally via sentence-transformers, and graph traversal runs via NetworkX. If no key is set, the API responds with a structured retrieval-only payload containing top hybrid code snippets and graph paths without throwing an error.

In context_builder.py, we enforce a strict 24,000 character limit (~6,000 tokens). Candidates are packed in descending score order. If the next chunk would overflow, we calculate remaining capacity and cleanly slice it with ... (context budget reached) rather than exceeding the budget or breaking mid-token.

Both BFS traversal and impact analysis maintain explicit visited sets and bounded depth limits (depth 2 for retrieval, depth 3 for impact analysis). Circular callers are recorded once and never re-enqueued.
